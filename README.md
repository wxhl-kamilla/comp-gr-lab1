# Лабораторная работа № 1 — вариант 3: параллелепипед

Исходный проект преподавателя дополнен сценой Vulkan. Есть перспектива и ортографическая проекция, управление переносом, вращением и масштабом, анимация с паузой и настройками, цвет в ImGui, процедурные цвета вершин и второй экземпляр фигуры с отдельным `VkDescriptorSet`. Используются Vulkan, GLFW, ImGui и C++20.

## Как собрать на Windows

1. Установите Visual Studio 2022 с компонентом «Разработка классических приложений на C++», CMake и [Vulkan SDK](https://vulkan.lunarg.com/sdk/home). В составе SDK нужен `glslc`; после установки откройте новый терминал и проверьте `glslc --version`.
2. Откройте терминал в каталоге, где лежит этот файл. Выполните `cmake --preset msvc-debug`, затем `cmake --build build-debug --config Debug`.
3. Из этого же каталога запустите `build-debug/Debug/vulkan-starter-app.exe`. Для первого запуска нужен доступ CMake к GitHub: `FetchContent` скачивает зависимости преподавателя. Путь к шейдерам задаёт CMake, поэтому запуск из Visual Studio и из терминала работает одинаково.
4. Если в Visual Studio проект уже открыт, скопируйте `source/` и `shaders/` в ваш клон, замените `CMakeLists.txt`, обновите конфигурацию и соберите. Оставшиеся исходники преподавателя уже включены здесь.

Без Vulkan SDK, `glslc` и загруженных зависимостей сборка невозможна. Если окно открылось, проверьте переключатель Perspective projection, движение ползунков Position/Rotation/Scale, Pause animation, Orbit speed/Orbit radius, Color multiplier и Second object. В консоли не должно быть сообщений validation layers.

## Зачем нужны файлы

- `source/main.cpp`: окно GLFW, цикл приложения и порядок вызовов. Он вызывает `update()`, затем получает кадр и вызывает `render()`.
- `source/graphics_internal.*`: код преподавателя для инициализации Vulkan, изображения окна, глубины и ImGui. Исправлена ветка сообщения в `submitAndPresent()`, где успех ошибочно выдавался за сбой.
- `source/application.cpp`: вся логика лабораторной: геометрия, матрицы, буферы, дескрипторы, интерфейс, команды рисования и удаление ресурсов.
- `shaders/box.vert` и `shaders/box.frag`: программы GPU для вершин и пикселей. CMake вызывает `glslc`, создавая файлы `.spv`.

## Как устроена сцена (читать вместе с кодом)

### Сначала — геометрия и математика

`Vertex` содержит три координаты позиции и три компоненты цвета. В цикле создания `vertices` три младших бита числа `i` выбирают отрицательный или положительный X, Y, Z. Получаются 8 углов с полуразмерами 0.8, 0.5 и 0.4. Это **параллелепипед**, размеры его сторон равны 1.6, 1.0 и 0.8. Для цвета каждый X/Y/Z переводится в диапазон 0.25–1.0. Это дополнительное задание 5: цвет выводится формулой из *локального положения*, а не прописывается для каждого угла вручную.

`indices` группируются по три числа: каждая тройка задаёт один треугольник. Всего 12 треугольников (по два на грань), то есть 36 индексов. Вершины используются повторно. Соответствие: лекция 3, слайды 2–5 и 8–10.

`Mat4` — матрица 4×4 из 16 чисел. `identity()` создаёт единичную матрицу, `multiply()` перемножает матрицы, `translate()` переносит, `scale()` растягивает, `rotateX/Y/Z()` вращают. `m[column * 4 + row]` означает размещение по столбцам для GLSL. Угол переводится из градусов интерфейса в радианы для `sin()` и `cos()`.

При умножении `projection * view * model * vec4(position, 1)` сначала фигура преобразуется в мире, потом относительно камеры, затем проецируется на экран. `view` отодвигает мир на 8 вдоль отрицательного Z: это эквивалент камеры на Z=+8. `perspective()` создаёт сужение с расстоянием при угле обзора 55°, а `orthographic()` сохраняет параллельность; обе используют отношение ширины к высоте окна (`aspect`) и допустимую Vulkan-глубину 0…1. Соответствие: лекция 1, слайды 15–29. Параметр near=0.1 задаёт ближайшую видимую плоскость, far=100 — дальнюю.

### Затем — ресурсы Vulkan

`Buffer` хранит `VkBuffer` (описание буфера для GPU) и `VmaAllocation` (выделенную VMA память). `createBuffer(bytes, usage, target)` задаёт размер, назначение и возможность записи с CPU. `writeBuffer` получает адрес памяти через `vmaMapMemory`, копирует байты через `memcpy`, сбрасывает кэш вызовом `vmaFlushAllocation` и снимает отображение. Это используется для массива вершин, индексов и двух `Uniform`. Соответствие: лекция 3, слайды 14–23.

`Uniform` содержит матрицу `mvp` и цвет `tint`. Шейдер видит его по `layout(set=0,binding=0)`. `VkDescriptorSetLayout` описывает один uniform-буфер, доступный вершинному шейдеру. `VkDescriptorPool` резервирует **два** дескриптора и **два** набора; `vkAllocateDescriptorSets` выдаёт два набора, `vkUpdateDescriptorSets` связывает каждый со своим uniform-буфером. Соответствие: лекция 3, слайды 24–31. Два набора выполняют задание 6.

`shader()` считывает скомпилированный SPIR-V и создаёт `VkShaderModule`. `createPipeline()` указывает вершинный и фрагментный шейдеры, разметку `Vertex`, треугольники, заливку, проверку глубины, формат цвета и `render_pass` из стартового кода. `pipelineLayout` сообщает конвейеру, как устроены дескрипторы. Соответствие: лекция 2, материал про графический конвейер и модули шейдеров.

### Каждый кадр

`update(time)` получает время в секундах. `delta` — время между кадрами с ограничением 0.1 с при зависании окна. Если анимация не остановлена, `phase` увеличивается на `speed * delta`. `ImGui::Checkbox`, `DragFloat3`, `SliderFloat`, `ColorEdit3` меняют значения переменных сразу в памяти приложения. Начальные значения находятся над `createBuffer()`; их можно изменить. Ползунки изменения масштаба ограничены значениями от 0.1 до 4.

`render(fd)` берёт `fd.command_buffer` и `fd.framebuffer` из стартового кода. `orbit` даёт движение по окружности в XZ и колебание по Y; к поворотам добавляется угол, зависящий от фазы. Два `models` определяют размещение экземпляров. Для каждого экземпляра рассчитываются свои `mvp` и uniform. Запись uniform происходит **после** `prepare()`, где стартовый код ждёт fence предыдущего кадра: GPU уже закончил читать прежние значения.

Далее `vkBeginCommandBuffer` начинает запись команд; `vkCmdBeginRenderPass` очищает цвет и буфер глубины; `vkCmdBindPipeline` выбирает программу рисования; `vkCmdSetViewport` и `vkCmdSetScissor` задают область окна; `vkCmdBindVertexBuffers` и `vkCmdBindIndexBuffer` подключают геометрию. Для каждой фигуры `vkCmdBindDescriptorSets` подключает её набор ресурсов, `vkCmdDrawIndexed(..., 36, 1, 0, 0, 0)` рисует 36 индексов, один экземпляр за вызов, без смещений. Потом проход и запись команд заканчиваются. В `main.cpp` стартовый код отправляет команды на GPU и показывает кадр. Соответствие: лекция 2, команды рисования; лекция 3, привязка дескрипторов.

`shutdown()` ждёт окончания работы GPU, удаляет pipeline, layout, пул, layout набора и все буферы. Парность функций создания/удаления важна для validation layers.

### Что делают аргументы в наиболее важных вызовах

| Вызов | Аргументы по порядку |
| --- | --- |
| `vkCreateDescriptorPool(device, &info, nullptr, &pool)` | GPU-устройство; адрес описания; стандартный аллокатор CPU; адрес переменной результата |
| `vkCmdBindDescriptorSets(cmd, GRAPHICS, layout, 0, 1, &set, 0, nullptr)` | командный буфер; графический конвейер; описание ресурсов; первый набор №0; число наборов 1; адрес набора; число динамических смещений 0; их отсутствие |
| `vkCmdBindVertexBuffers(cmd, 0, 1, &buffer, &offset)` | команда; первый слот 0; один буфер; его адрес; смещение 0 байт |
| `vkCmdDrawIndexed(cmd, 36, 1, 0, 0, 0)` | команда; 36 индексов; один экземпляр; первый индекс 0; добавка к номеру вершины 0; первый экземпляр 0 |
| `vkCmdBeginRenderPass(cmd, &pass, INLINE)` | команда; описание прохода; последующие команды записываются прямо в этот же буфер |

## Ограничения проверки

Исходники собраны в правильной структуре и сверены с присланным стартовым кодом, но здесь отсутствуют Vulkan SDK и `glslc`, а зависимости CMake находятся на GitHub. Поэтому реальную сборку и запуск нужно проверить на компьютере с установленным SDK. При первой ошибке компиляции или сообщении validation layers пришлите **полный текст** ошибки и файл/строку, я поправлю конкретное место.
